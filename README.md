# ZimaOS Login Demo

Minimal single-file Go demo packaged as a systemd-sysext raw image.

## Defaults

- Module name: `zimaos-login-demo`
- Installed version in raw manifest: `v1.0.0`
- Target version API response: `v1.0.1`
- API port: `49321`
- API and WebSocket prefix: `/v2/api/rt`
- Frontend entry: `/modules/zimaos-login-demo/index.html`
- Demo credentials: `admin` / `zimaos`
- Backend source: `main.go`
- Frontend source: `web/static/`

## API

- `GET /v2/api/rt/healthz`
- `POST /v2/api/rt/login`
- `GET /v2/api/rt/target-version`
- `GET /v2/api/rt/auth-probe`
- `GET /v2/api/rt/ws` WebSocket echo endpoint

On startup, the backend tries to register this route with `casaos-gateway` by reading `/var/run/casaos/management.url`:

```json
{"path":"/v2/api/rt","target":"http://127.0.0.1:49321"}
```

Example:

```bash
curl -s http://127.0.0.1:49321/v2/api/rt/target-version
curl -s -X POST http://127.0.0.1:49321/v2/api/rt/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"zimaos"}'
```

The frontend loads `/modules/zimaos-login-demo/config.js`, which is generated by `scripts/build-raw.sh` with a UTC build id. If the page refreshes but still shows an old build id, the stale content is outside the Go backend path: check whether the new raw package was installed, whether the sysext was refreshed, and whether the browser/gateway cached the static module file.

## Build

```bash
make test
make build
make raw
```

`make raw` requires `mksquashfs` from `squashfs-tools`. It creates:

```text
zimaos-login-demo.raw
```

## Raw Layout

```text
raw/usr/bin/zimaos-login-demo
raw/usr/lib/systemd/system/zimaos-login-demo.service
raw/usr/share/casaos/www/modules/zimaos-login-demo/index.html
raw/usr/share/casaos/www/modules/zimaos-login-demo/logo.svg
raw/usr/share/casaos/modules/zimaos-login-demo.json
raw/usr/lib/extension-release.d/extension-release.zimaos-login-demo
```

The module name, raw filename, manifest name, and extension-release suffix are all `zimaos-login-demo`.
