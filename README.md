# Mod Management Playground

Minimal ZimaOS raw module playground for mod management scenarios, experiments, and integrations.

## Defaults

- Module name: `rt`
- UI title: Mod Management Playground
- Installed version in raw manifest: `v1.0.1`
- Target version API response: `v1.0.1`
- API port: `49321`
- API and WebSocket prefix: `/v2/api/rt`
- Frontend entry: `/modules/rt/index.html`
- Local test credentials: `admin` / `zimaos`
- Backend source: `main.go` using `github.com/go-chi/chi/v5`
- Frontend project: `web/` with Bun, Vite, SolidJS 2.0 beta, and TailwindCSS

## API

- `GET /v2/api/rt/healthz`
- `POST /v2/api/rt/login`
- `GET /v2/api/rt/target-version`
- `GET /v2/api/rt/ws` WebSocket echo endpoint

On startup, the backend tries to register this route with `casaos-gateway` by reading `/var/run/casaos/management.url`:

```json
{"path":"/v2/api/rt","target":"http://127.0.0.1:49321"}
```

Example:

```bash
curl -s http://127.0.0.1:49321/v2/api/rt/target-version
curl -s -X POST http://127.0.0.1:49321/v2/api/rt/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"zimaos"}'
```

The frontend loads `/modules/rt/config.js`, which is generated by `scripts/build-raw.sh` with the local module version. The module reads Zima WebUI tokens from `localStorage`; if a deployed module path has no access token, it redirects to the WebUI login route and asks it to return to the current URL. These auth, API, version, and WebSocket probes are kept as integration surfaces for trying mod management flows.

## Build

```bash
(cd web && bun install)
(cd web && bun run test)
go test ./...
(cd web && bun run dev)
(cd web && bun run build)
bash scripts/build-raw.sh
```

## Docker

This project can run as a standalone Docker service. The container builds the
Solid/Vite frontend, serves it from the Go process, and enables self-signed
HTTPS by default:

```bash
docker compose up --build
```

Open:

```text
https://127.0.0.1:49322/modules/rt/index.html
```

The certificate is self-signed, so the browser will ask you to trust it before
microphone access works. HTTP is still exposed at:

```text
http://127.0.0.1:49321/modules/rt/index.html
```

Useful runtime environment variables:

```text
RT_HTTP_ADDR=:49321
RT_ENABLE_HTTPS=true
RT_HTTPS_ADDR=:49322
RT_CERT_FILE=/data/certs/rt.crt
RT_KEY_FILE=/data/certs/rt.key
RT_AUTO_SELF_SIGNED_CERT=true
RT_PUBLIC_HOSTS=localhost,127.0.0.1
RT_STATIC_DIR=/app/static
RT_SKIP_GATEWAY_REGISTRATION=true
```

`RT_PUBLIC_HOSTS` should include the LAN IP or DNS name you use in the browser
if you do not open the app through localhost.

Deploy to a ZimaOS box and verify the mounted `/usr` tree:

```bash
scripts/deploy-to-zima.sh 10.0.0.85
```

The deploy script checks that `/usr/share/casaos/www/modules/rt/config.js` is available after `systemd-sysext refresh`.

`scripts/build-raw.sh` requires `mksquashfs` from `squashfs-tools`. It creates:

```text
rt.raw
```

## Source Layout

`web/` contains the frontend Bun/Vite project. `cd web && bun run build` writes local generated files to ignored `web/static/`. `scripts/build-raw.sh` builds the frontend from `web/` directly into a temporary raw root, then stages `config.js`, the CasaOS manifest, and the Go binary before creating the raw image.

```text
main.go
web/package.json
web/bun.lock
web/vite.config.ts
web/tsconfig.json
web/index.html
web/src/App.tsx
web/src/auth.ts
web/src/api.ts
raw/usr/lib/systemd/system/rt.service
raw/usr/lib/extension-release.d/extension-release.rt
```

## Generated Raw Layout

```text
/usr/bin/rt
/usr/lib/systemd/system/rt.service
/usr/share/casaos/www/modules/rt/index.html
/usr/share/casaos/www/modules/rt/logo.svg
/usr/share/casaos/modules/rt.json
/usr/lib/extension-release.d/extension-release.rt
```

The module name, raw filename, manifest name, and extension-release suffix are all `rt`.
